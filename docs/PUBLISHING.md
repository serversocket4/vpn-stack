# Публикация и GitHub MCP

## Подключение GitHub

В приложении, из которого работает агент, подключите GitHub-коннектор/MCP и авторизуйтесь в своём GitHub-аккаунте. Выберите нужные репозитории. Доступ к одному приватному репозиторию не даёт автоматически доступ ко всем остальным.

Для чтения достаточно разрешений чтения содержимого. Для создания ветки или коммита нужен доступ на запись содержимого выбранного репозитория. Создание самого репозитория может требовать отдельной операции или выполнения в интерфейсе GitHub. Если подключённый вариант предоставляет только чтение, публикацию выполняют через поддерживаемый им Git/CLI-процесс либо интерфейс GitHub; не считайте коннектор с чтением разрешением на запись.

Задача для агента должна указывать репозиторий, ветку и каталог исходников. Например:

```text
Опубликуй проверенную чистую папку vpn-stack в OWNER/vpn-stack,
в ветку main, одним начальным коммитом. Рабочие конфиги и историю
приватного проекта не добавляй.
```

Токен GitHub не помещают в репозиторий, переписку, адрес remote или файлы настроек приложения. Используйте авторизацию коннектора либо штатный менеджер учётных данных.

## Чистое дерево перед первым коммитом

Публикуют только исходники, документацию, лицензии, тесты и шаблоны. Не копируют весь домашний каталог, папку работы агента или историю существующего приватного Git-репозитория.

В публичном дереве не должно быть:

- токенов Telegram/GitHub, chat ID, рабочих паролей и хешей сессий;
- приватных ключей SSH/REALITY/TLS и действующих UUID пользователей;
- реальных ссылок и QR-кодов подписок, MTProto-секретов и пользовательских комплектов;
- БД админки, истории мониторинга, журналов, сетевых захватов и резервных копий;
- действующих адресов и доменов своей инфраструктуры, имён клиентов и локальных пользовательских путей;
- каталога runtime, заполненного env или приватного JSON параметров.

Примеры содержат только демонстрационные адреса и незаполненные значения. Все доступы для новой установки создаются заново. `.gitignore` помогает избежать случайного добавления runtime, но не удаляет уже проиндексированный секрет: проверяйте именно содержимое будущего коммита.

## После публикации

Проверьте дерево репозитория и первый коммит через GitHub. Сверьте число и состав файлов с чистой локальной папкой. Публикация исходников не должна менять конфигурацию или службы действующих VPS.

Если секрет всё же попал в публичный коммит, сначала отзовите или замените его в соответствующем сервисе. Удаление файла следующим коммитом оставляет старое значение в истории.
